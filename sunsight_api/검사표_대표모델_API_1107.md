## 2. 피처 계산 (07 `photo_features`와 같은 식)

사진을 긴 변 640px로 줄인 뒤 계산한다. 하늘 = 위 1/3, 도로 = 아래 1/3.

| 피처 | 식 | 확인 |
| --- | --- | --- |
| sky_mean | 하늘 회색 평균 ÷ 255 | |
| blue_sky | 하늘에서 H 90~130 · S≥50 · V≥100 비율 (OpenCV HSV) | |
| white_ratio | 전체에서 회색 ≥250 비율 | |
| shadow_contrast | 도로 회색 (90분위 − 10분위) ÷ 255 | |
| road_mean | 도로 회색 평균 ÷ 255 | |
| sky_road_ratio | (하늘 평균+1) ÷ (도로 평균+1) | |
| portal_ratio | log10(주변 고리 평균+1 ÷ 구멍 평균+1). 구멍 = 가운데 1/2 영역의 가장 어두운 15%, 고리 = 구멍을 41px로 넓힌 테두리 | |
| saturation | 전체 S 평균 ÷ 255 | |
| spread | 전체 회색 (95분위 − 5분위) ÷ 255 | |
| mean_all | 전체 회색 평균 ÷ 255 | |
| sun_alt | NOAA 근사식, 입력 시각은 한국 시각(KST) → UTC로 바꿔 계산 | |
| cloud | ASOS 전운량 0~10. 안 주면 학습 중앙값 | |

## 3. API를 만들며 내가 정한 것 (확인 필요)

| 번호 | 정한 것 | 이유 · 위험 | 확인 |
| --- | --- | --- | --- |
| A | C=0.01을 고정값으로 씀 | 10 노트북은 매번 학습 OOF로 {.01, .1, 1} 중 고름. 11/6 결과가 .01이라 고정 | |
| B | 사진의 터널 구멍은 항상 "가운데 어두운 15%"로 찾음 | Mapillary 시험과 같은 방식. 71786 학습은 라벨 다각형을 썼으니 학습과 시험 방식이 원래 다름 (10과 같은 조건) | |
| C | `grade_prob` (하 = 1−p1, 중 = p1(1−p2), 상 = p1·p2) 추가 | 노트북에는 없던 값. 화면 게이지용. 사고 확률 아님이라고 README에 적음 | |
| D | `est_luminance_ratio` (추정 밝기 ÷ 280×조광)를 화면 "N배"용으로 냄 | 등급과 62%만 일치 → 화면에 "12배인데 하"가 나올 수 있음. 숫자를 보여줄지, 등급만 보여줄지 형 판단 필요 | |
| E | 경고 거리 155m, 경계부 80m, 경고 문구 3개 | 11/5 구간 길이 결정과 같은 숫자. 문구는 내가 쓴 초안 | |
| F | 출구 입력은 받지 않음 (입구만) | 11/5 · 11/6 형 결정 | |
| G | 모델 파일은 형 PC에서 `train_model.py`로 다시 만들기 | 클라우드 scikit-learn 1.9.1로 만든 joblib은 다른 버전에서 경고·오류가 날 수 있음 | |

## 4. 형 PC에서 다시 확인하는 법

```
cd sunsight_api
pip install -r requirements.txt
python train_model.py --train ../sunsight_video/data/aihub_71786/학습표_71786.csv --test ../sunsight_video/data/시험표_mapillary.csv --ref ../sunsight_video/data/등급2단계_사진별.csv
python verify_api.py ../sunsight_video/data
```

기대 출력: `Macro F1 0.844`, `등급 일치 66 / 66`, 사진 입력 `등급 일치 66 / 66` (형 PC에는 사진이 다 있음).
